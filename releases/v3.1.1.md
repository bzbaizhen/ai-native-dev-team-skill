## English

This policy-only maintenance release reduces repeated handoffs without weakening acceptance:

- Group closely coupled work by bounded user behavior rather than individual files or UI micro-steps.
- Preserve tests-only RED, Main confirmation, GREEN, proportionate checks, and independent final validation. A separate RED-fixture review is conditional, not routine.
- Reuse authenticated test evidence only when complete candidate identities, execution inputs, original logs, and inner exit codes agree. Independent semantic review remains required for material work.
- Bound transient-failure investigation, retain the first failure, and do not substitute instrumented success for a failing standard acceptance command.
- Continue already-authorized stages on completion; honor pauses, blockers, and the approved round cap. Keep one five-minute watchdog owner, not another heartbeat.
- Keep Linear's current frontier clear and retain important milestone receipts instead of routine polling comments.
- Respect explicit host transport requirements and existing stricter task contracts. Model routes, runtime Profiles, permissions, and publication gates are unchanged.

No runtime engine implementation or provider configuration is included. These are workflow instructions, not scheduler enforcement or a measured speedup claim. Existing sessions must reload the affected references to use the updated policy.

## 简体中文

本次仅维护工作流规则，减少重复交接，同时保留验收边界：

- 按有明确边界的用户行为组合任务，避免按文件或界面微步骤反复切片。
- 保留 tests-only RED、Main 确认、GREEN、相称检查与最终独立验证；额外 RED 测试审查改为具体疑点触发。
- 只有完整候选身份、执行输入、原始日志和内部退出码一致，才复用测试证据；实质工作仍需独立语义审查。
- 有界调查瞬时失败，保留最初失败，不拿带诊断改造的成功替代失败的标准验收命令。
- 完成后继续已授权阶段，遵守暂停、阻断和批准轮数上限；只保留一个五分钟 watchdog 负责人，不增加 heartbeat。
- Linear 维护清楚的当前状态和重要里程碑，避免轮询流水账。
- 尊重宿主明确的传输要求及既有更严格任务合同；模型路由、运行 Profile、权限和发布门禁不变。

不包含开发引擎实现或 Provider 配置。这些是工作流指令，不代表调度器强制执行或已实测提速。已有会话需重新读取相关参考文件。
