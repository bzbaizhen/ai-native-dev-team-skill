## Candidate addition

RC.5 replaces bare candidate-to-stable ancestry with an explicit, verifier-recomputed `integration_proof` for accepted trials:

- `same_commit` accepts only when candidate and stable Commit SHAs are equal and the stable Commit remains on the registered stable branch;
- `same_tree` accepts a non-ancestor squash result only when a full retained candidate ref resolves to the exact candidate Commit, both Commit trees are recomputed by Git and equal, and the Manifest and acceptance evidence carry identical proof fields;
- `same_tree` has a strict `tree_scope` with `history_sensitive: false` and no non-tree dependencies. History-sensitive behavior, LFS/filter output, submodule working-tree content, generated files, and external dependencies require exact stable-Commit validation;
- `same_tree` reports evidence carried by exact tree identity. It does not claim QA was rerun on the stable Commit.

The release gate also rejects non-string proof-bound SHA, digest, and ref values through controlled validation instead of incidental type errors.
