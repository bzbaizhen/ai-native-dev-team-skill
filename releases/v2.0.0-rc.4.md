# v2.0.0-rc.4 candidate

Status: local release candidate. This record does not indicate a Push, Tag, GitHub Release, installation update, stable V2 acceptance, remote anchor, or a counted real trial.

## Baseline

- Independently validated RC.3 baseline: `04a5bd8cd25c6bff5537cc3345d5387f2d7f020e`.
- Immutable V1 recovery point: Tag `v1.0.0` at Commit `1ebec8135937fd63d03daf3cdff4e0b7cb740490`.

## Candidate addition

RC.4 closes a remaining source-integrity gap in V1 comparability:

- every frozen V1 baseline object now enumerates a non-empty set of supporting source blobs from the same freeze Commit;
- each source has a unique ID, evidence kind, source revision, normalized relative POSIX path, SHA-256 digest, and explicit supported claims;
- the complete set must support task identity, exact C/R/topology stratum, and acceptance;
- formal-efficiency eligibility additionally requires a `metrics_record` supporting the efficiency denominator;
- the verifier reads and hashes every source blob from the exact freeze Commit and rejects missing blobs, digest mismatch, duplicate IDs or paths, path escape, incomplete claims, and unsupported claim kinds;
- public examples are synthetic and deliberately ineligible for formal efficiency analysis.

## Evidence boundary

Content-addressing proves which bytes were frozen and detects later substitution. It does not prove that historical source content is truthful, that its classification is correct, or that a local anchor was remotely protected. Human source qualification and an independently trusted freeze/head record remain mandatory.

## Dogfood boundary

This release-gate correction changes the Skill candidate and cannot count toward its own five-task sample. Formal trials start only after the final RC.4 Commit, qualified private V1 sources, and external freeze/head control are fixed.

- Any real-task count toward the five-task gate.
