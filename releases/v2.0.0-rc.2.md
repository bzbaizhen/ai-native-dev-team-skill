Status: local release candidate. This file does not indicate a Push, Tag, GitHub Release, installation update, or stable V2 acceptance.

## Candidate addition

RC.2 adds a deterministic stable-release gate:

- an externally supplied Git freeze/head pair whose linear history freezes the source roster, appends one immutable receipt per `task_ready`, and ends with a dedicated closure Commit that anchors the final Manifest digest;
- schemas for the frozen roster, registration receipts, closure, request/acceptance evidence, and trial Manifest;
- one continuous preregistered sequence whose task universe comes from the anchor history rather than the mutable Manifest;
- unique `(candidate, project evidence identity, task_id)` counting and source-level complete-ledger audit across the candidate window;
- verification of frozen ledger prefixes, full-ledger snapshots, task evidence digests, candidate-to-stable ancestry, and stable-branch ancestry;
- exact equality between each comparable V1 stratum and its registered complexity/risk/topology;
- fail-closed handling when a source, trial, order position, evidence object, hard gate, quality guardrail, or recovery fact is missing or inconsistent;
- protection against task duplication, omission of an early failure, sequence rewriting, self-rehashed registry replacement, unanchored work, and replacement by a later success;
- a separate 15-task accepted-sample threshold for formal efficiency analysis;
- public inclusion rules and an anonymized manifest example.

## Dogfood boundary

The release-gate implementation task changes the Skill candidate itself. It is retained as a real pre-freeze dogfood task but is not eligible for the five-task stable-release sample.

The five comparable tasks start only after the final RC.2 Commit is fixed. They must use that exact Skill candidate and enter their own project stable branches.

## Deliberately not claimed

- Stable `v2.0.0` acceptance.
- Any real-task count toward the five-task gate.
- A measured efficiency improvement over V1.
- Push, Tag, GitHub Release, installation update, or public publication.
- Proof that a local Git ref was remotely protected or when a receipt was pushed. The trusted freeze/head pair must come from an independent protected ref, signed record, or trusted timestamp service.
